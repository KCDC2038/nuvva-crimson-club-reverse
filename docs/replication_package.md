## 一、开箱即用的 System Prompt（复制即用）

## 二、Nuvva 原版架构（逆向还原）

```
┌─ 浏览器 SPA (Vite+Vue3, m.nuvva.ai/assets/mobile-*.js)
│    └─ localStorage: user_id + access_token(JWT) + refresh_token
│
├─ REST API (同域 /api/v1/*, JWT 鉴权)
│    auth/*, user/*, chat/list, chat/create, chat_topic/*(create/branch/pin/delete)
│    chat_topic_spec/get|update   ← 话题级配置(rules/agentNotes/loadedSkills/skillFilesMap/blockMemory)
│    screen_share/get|set_data|get_data|handle_event
│    file/upload|list|fetch|create|delete   ← 技能即文件（mainEntryFile 主入口文件）
│    agent/list|update, pricing_plan/list, user_subscription/get, payment/*
│
├─ WebSocket wss://m.nuvva.ai/ws?user_id=<uuid>
│    {type, content(JSON字符串)} 帧：33=思考中状态 52/53=话题元数据(含agent) 101=新消息 201=屏幕推送
│
├─ 屏幕机制（技能的核心玩法）
│    模型回复 → 服务端把 HTML 存 cdn.nuvva.ai/screen_share/<uuid>.html
│    → WS 201 帧(contentUrl) → 前端 fetch → Blob → <iframe class="screen-iframe">
│    iframe 内注入 window.ld()/getData()、window.sd()（状态读写，走 screen_share/get_data|set_data）
│    和 window.te(text) → screen_share/handle_event {eventMessage, screenContent(整份HTML快照)}
│    → eventMessage 作为一条用户消息进会话 → 模型结合状态推演 → 生成新屏幕 → 循环
│
└─ 技能分发
     技能 = 服务端文件记录（name/description/topicSpec/mainEntryFile/blockMemory）
     按 ID 寻址（CHTKMXRTNSZN）。话题规范为空 → prompt 由服务端按 ID 注入模型上下文。
     用户端无任何 API 能读到技能正文（文件页/智能体页/话题规范均空）。
```

**关键工程点**（复刻时要实现的三件事）：
1. **屏幕即输出**：模型每轮可输出完整 HTML，服务端持久化 + URL 推送 + iframe 沙箱渲染；
2. **双向桥**：iframe 里 sd/ld/te 三个全局函数把「状态读写 + 用户点击」桥回会话（te 的事件文本会变成一条用户消息，同时携带当前 HTML 快照让模型知道 UI 现状）；
3. **状态外置**：游戏数值存在服务端（`screen_share/set_data`），与会话绑定，模型靠读状态保持跨轮一致。

## 三、低成本使用方案（按成本从低到高）

**方案 A · 纯文本版（零开发，成本≈0）**
把第一节的 prompt 贴进任意 AI 客户端（ChatBox/NextChat/SillyTavern/官方网页均可），再加一句：
> 「本局全程纯文本运行：用文字描述界面状态（导航栏/数值面板/A·B·C·D 选项），不要生成 HTML。」
省掉每轮 5-13KB 的 HTML 输出（Nuvva 上点每个导航按钮都会触发整屏重绘，这是它最烧能量点的地方）。体验损失仅剩视觉包装。

**方案 B · 半图形版（低开发）**
方案 A 基础上，用 SillyTavern/自建前端固定渲染一个通用 UI 壳（顶部状态条 + 中间叙事 + 底部 A/B/C/D 按钮），让模型每轮只输出 JSON：`{narrative, reputation, stamina, excitement, options:[A,B,C], npc:{...}}`。UI 由壳渲染，模型零 HTML 输出，图形感与成本兼得。

**方案 C · 全复刻版（对齐原版体验）**
自建第一节的架构：任意 LLM API + 上述屏幕机制（HTML 生成 → 对象存储 → iframe 渲染 + postMessage 桥）。模型建议用 Claude Sonnet 级别（HTML 质量与长规则遵从最好）。注意把「重绘条件」写死（第一节第 9 条），否则每轮都重画 HTML，成本会失控。

**成本对比**：Nuvva 能量包 1000点/$3.99 起，一次建档+一个导航点击就是两次整屏 HTML 生成。方案 A/B 走自己的 API key，一轮纯文本 ≈ 原版一轮屏幕成本的 1/10。

## 四、仍缺失/无法获取的部分

- **技能正文原文**：服务端注入、用户端不可见；六种话术（直接索要/换说法/交接文档/英文/JSON/角色扮演）全部被输出层拦截（`bee-bee-bee-`）。本文档是从行为与产物反推的**等价重建**，非逐字原文。
- 声望等级/称号体系、道具九大类明细：待新账号补测（probe7 已就位）。
- 后端模型型号：不在前端 bundle，无法从客户端确定。
